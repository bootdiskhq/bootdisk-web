# Source investigation explanations

The detail page shows a source-bound explanation where Catalog supplies one.
Unexplained issues retain the existing generic warning. Wrong-source explanations
fall back to that warning; all text is rendered through textContent. Rule 1, 2
and 3 catalog projections are accepted; completed investigations must carry the
same manifest and entry key as the source post.

Visible explanation text participates in public update comparison. This changes
the projection contract to bootdisk-public-updates-v4 / visible-v4. Private
completion dates and evidence hashes do not create public updates. Old v3
registers must be rebuilt from the published snapshots with their actual existing
timestamps, not reset or assigned new publication dates.

Acceptance against rc11–rc16 preserves all 394 historic events exactly. The
candidate changes ten visible source notes and adds no entries. The local
candidate preview deliberately has no new publication event; recording its
publication timestamp belongs to the later release step. The rebuilt rc16
history is retained separately, ready for that step.

All 426 posts and 832 images passed local HTTP verification. Source prose,
original documents, software decisions and archive index are unchanged.
